## Project Overview

GameShutter is an iPad-optimized iOS app for sports video recording with in-video highlight clipping. Deployment target: iOS 12.4 (the target-level setting; the project-level 11.2 is overridden), Swift 5 — so iOS 13+ APIs (e.g. `.builtInTripleCamera`/`.builtInDualWideCamera`) must stay behind `#available(iOS 13.0, *)` checks, as the existing code does. No CocoaPods — use `.xcodeproj` directly.

**Branch lineage:** `Highlight_only` stripped the BLE gimbal/remote stack, scoreboard overlay, team config UI, and the old compass/heading display (`729c26f`) down to bare camera recording + highlights. `CourtSurvey_detection` later re-added a `CLLocationManager` heading HUD, a timed-metadata track (`mdta/com.camcourt.*`), and a YOLO-based Court Survey phase (`CourtSurveyor.swift`, `bbp_v7.mlpackage`) — **all three have since been deleted from this folder**, so the app is back to camera recording + watermark + highlights only. None of the removed code exists here: don't assume anything referencing `BLE_stack/`, `scoreBoardData`, `teamElement`, `LocationDelegate`, `CLLocationManager`, `CompassOverlayView`, `CourtSurveyor`, or a `VideoWriter` metadata input is available. **This folder has no git history** (it was removed after copying); the commits and branches named above live only in the original repo at `~/Documents/CamCourt` (remote `github.com/HenryZhang2000/CamCourt`) — look there for `git log`/`git branch` or to recover removed features.

`README.md` is the user-facing GameShutter overview (features, requirements, build commands, project layout, privacy). It replaced a stale README from the upstream "MagicVideo" sample this project was forked from; keep it in sync when features change. Source headers, comments and the project file carry no copyright lines or original-author names any more (the org name is `GameShutter`), and the per-user `xcuserdata` folders were deleted. Don't reintroduce either.

## Build Commands

```bash
# Build for simulator
xcodebuild build -project GameShutter.xcodeproj -scheme GameShutter -destination 'generic/platform=iOS Simulator'

# Build for connected device
xcodebuild build -project GameShutter.xcodeproj -scheme GameShutter -destination 'generic/platform=iOS'

# Clean build
xcodebuild clean -project GameShutter.xcodeproj -scheme GameShutter

# Regenerate branding bitmaps (standalone scripts, not in the app target)
swift Tools/render_app_icon.swift GameShutter/Assets.xcassets/AppIcon.appiconset
swift Tools/render_watermark.swift GameShutter/Assets.xcassets/GameShutterWatermark.imageset/GameShutterWatermark.png <font-dir>
#   <font-dir> must contain BarlowCondensed-ExtraBoldItalic.ttf and BarlowCondensed-MediumItalic.ttf (Google Fonts, OFL)
```

No unit tests exist. Testing is done on physical devices — camera and highlight-clip export require hardware (simulator camera feed is unusable for recording verification).

## Architecture

### Video Pipeline (`videoManager.swift`, owned by `CameraViewController` as `vManager`)

1. `setupCaptureSession()` configures an `AVCaptureSession` (`.high` preset) with a back camera (`.builtInTripleCamera` → `.builtInDualWideCamera` → `.builtInWideAngleCamera` fallback chain on iOS 13+), a front camera, and a mic input. Video output pixel format is forced to `kCVPixelFormatType_32BGRA` for CoreImage compatibility.
2. `videoManager` is the `AVCaptureVideoDataOutputSampleBufferDelegate` and `AVCaptureAudioDataOutputSampleBufferDelegate` for both outputs, each on its own queue (`Constants.QueueLabels.VideoSessionQueue` / `AudioSessionQueue`).
3. In `captureOutput(_:didOutput:from:)`: orientation is corrected via `CIImage.oriented(forExifOrientation:)` based on `isBackCameraActive` + `orientation`, then:
   - **Preview**: the corrected `CIImage` is drawn directly to a `GLKView` via `CIContext(eaglContext:)` — center-cropped to match the preview's aspect ratio.
   - **Recording**: the same `CIImage`, with the GameShutter logo composited over its bottom-right corner by `watermarked(_:)` (recording only — the preview stays clean), is rendered into a `CVPixelBuffer`, wrapped in a new `CMSampleBuffer`, and handed to `VideoWriter`. The watermark is a pre-rendered transparent PNG (`GameShutterWatermark` imageset, white lockup with baked-in shadow, regenerated by `Tools/render_watermark.swift` — not an app-target file) scaled to a fixed fraction of frame height and faded to 90%; the positioned result is cached per frame extent. Highlight clips inherit it since they're exported from the full recording. `ImageEffects.swift`'s CIFilter extensions are still unused dead code.
4. `VideoWriter` wraps `AVAssetWriter` to mux H.264 video + AAC audio into a `.mov`-typed file at `documents/video.mp4`. It defers `startSession(atSourceTime:)` until the first *video* frame arrives (avoids a leading black frame), then requires `isReadyForMoreMediaData` on both inputs before appending.
5. **Pause/resume**: `pauseRecording()`/`resumeRecording()` stop/restart the `AVCaptureSession` outright (not just the writer). `CMResumed`/`CMPausedTime`/`CMSkipTime` track the wall-clock gap and subtract it from every subsequent sample's presentation/decode timestamps, so the output video has no gap or pause artifact.
6. **Highlights**: tapping the highlight button sets `ishighLighting = true`; the next video frame captures `presentationTimeStamp - firstSamplebufTime` into `highLightArray` and resets the flag (so a tap always marks "now", not a stale timestamp). Each capture fires `videoManager.onHighlightCaptured(count)` on the main thread, which drives the orange count badge (`HighlightBadgeLabel`, a subview of the highlight button) in `CameraViewController` — it counts real captures, not taps, hides at 0, and resets to 0 on stop (`saveVideo()`) and on each new recording start; captures reported after `isCapturing` goes false are ignored so an in-flight frame can't re-show it after stop. On `stopRecording`, `generateHighLightClip()` runs one `AVAssetExportSession` per recorded timestamp against the just-finished full recording, exporting a `HighlightDuration`-second (default 10s, hardcoded — the Settings UI row for this is currently display-only and not wired up) clip ending 1s after the marked point, then `PhotosAlbumSaver.save` puts each clip in Photos, with its `creationDate` set to the wall-clock moment of the tap (`highLightDates`, parallel to `highLightArray`). Clips export and save concurrently, so their save time doesn't follow highlight order, and the editor's folder view sorts by `creationDate`. Each clip goes under a **GameShutter folder › `yyyy_MM_dd` album** (`Constants.PhotosAlbums`; Photos only nests albums inside folders, `PHCollectionList`, not inside other albums), creating either if missing. The date is fixed once per recording at stop time. Saves run one at a time on its serial queue with `performChangesAndWait`, so concurrent exports can't each create a duplicate folder or album; the local clip file is deleted after each save. The full video still goes to the library root. Highlights marked less than `HighlightDuration - 1`s into the recording are skipped (the clip wouldn't fit). Completion is tracked with a `DispatchGroup` that only real exports enter, so `generateHighLightClip`'s completion fires exactly once on every path, including when every highlight is skipped. Don't go back to shared counters incremented from the concurrent export callbacks.

**Saving to Photos** (`stopRecording`): `generateHighLightClip` reads the full recording via `AVAssetExportSession` *concurrently* with the main video's own `PHAssetCreationRequest.addResource`, so that resource creation uses `shouldMoveFile = false` (copy, not move) — moving/renaming the file out from under the still-in-progress highlight reads was a real race that could silently fail the main video's save. `cleanup()` deletes the local original afterward either way. **Save-or-delete prompt**: a user-initiated Stop (after the "Are you sure?" confirm) passes `confirmSaveFullVideo` to `stopRecording`, so recording stops immediately and a "Save Full Video?" alert appears once the file is finished; Delete skips the Photos save and calls `cleanup()` only after the `highlightsDone` `DispatchGroup` signals every highlight export finished (they read the same file), and only if no new recording has started. Highlight clips are saved either way. Background/termination stops pass `nil` and always save, since no prompt can be answered. A save failure calls `videoManager.onSaveFailed` (wired to an alert in `CameraViewController`) instead of only printing to the console.

**CIImage coordinate system**: bottom-left origin (unlike UIKit). Relevant to the watermark placement (bottom-right = max x, *min* y) and any other overlay compositing.

**Single video file**: recordings always write to `documents/video.mp4`, removed and recreated on each `startRecording()` — a new recording overwrites any prior unsaved one. Highlight clips get their own UUID-named temp files that are deleted after export.

**Finish serialization**: `videoManager` keeps the video capture queue (`videoCaptureQueue`) so `stopRecording()` can dispatch `markAsFinished()`/`finish()` through it rather than calling straight from the main-thread caller — appending to an `AVAssetWriterInput` after `markAsFinished()` throws, so finishing must be serialized after any in-flight or already-enqueued `videoOutput()` call. Keep routing it through that queue (this fixed a real video-not-saved bug when per-frame work was slower).

### Video Editor (iOS 13+)

A CapCut-style editor, opening in whichever orientation the device is held. The film button next to the gear (`CameraViewController.openVideoEditor`; disabled while recording, since presenting it tears down the capture session; hidden below iOS 13 because it uses SF Symbols throughout) first presents **`HighlightFoldersViewController`**: a grid of the date albums in the GameShutter Photos folder (newest first, empty albums hidden), each with its earliest video's thumbnail and a clip count. Picking one resolves its videos to file-backed `AVURLAsset`s via `PHImageManager.requestAVAsset` (iCloud download allowed; slo-mo/edited compositions that aren't single files are skipped) and presents the editor with them in `creationDate` order, oldest first. That initial layout isn't an undo step or an unexported change. The grid's last card, a "+" thumbnail labeled **Blank Project** (always shown, even with no folders or no Photos access), opens an empty editor, which goes straight to the clip picker. The top-right trash button toggles delete mode (button becomes **Done**): folder cards wiggle (`CAKeyframeAnimation` on the cell layer, random phase) with a red ✕ badge and the "+" card dims. Tapping a folder ends delete mode and confirms: **Delete Folder and N Clips** (`PHAssetChangeRequest.deleteAssets` for everything in the album, then the album itself) or **Remove Folder Only** (album only; clips stay in the library). iOS adds its own deletion prompt on top; declining it returns `PHPhotosError.userCancelled`, which is ignored rather than shown as an error. Closing the editor returns to the browser (which reloads on appear); the browser's ✕ is what returns to the camera and resets `AppDelegate.orientationMask`. Five files:

- **`EditorComposition.swift`**: the value-type model (`EditorProject` = `[EditorClip]` + optional `EditorAudio`; a clip is a time range of an `AVURLAsset`, so Split just makes two clips over the same file). `EditorCompositionBuilder.build` concatenates clips on one video track and composites frames with a **Core Image handler** (`AVMutableVideoComposition(asset:applyingCIFiltersWithHandler:)`) that rotates each frame upright from its source clip's `preferredTransform` and letterboxes it into the first clip's upright size. Don't switch back to layer instructions: an instruction-based composition, even AVFoundation's auto-generated one, left `AVPlayer` stuck at rate 0 with a black preview in the iOS 26 simulator, while the CI path plays and exports. Empty audio tracks are removed because they can stall playback/export. `EndingClipRenderer` renders a 2s logo-on-Ink card once to `tmp/gameshutter_ending_v2.mov` and reuses it; the ending is a normal clip with `isEnding`, always kept last.
- **`EditorTimelineView.swift`**: the scroll position *is* the playhead time (`contentInset` = half the width on each side; time = `(contentOffset.x + inset.left) / pointsPerSecond`). Programmatic moves go through `setCurrentTime` and don't report scrubs. Everything is rebuilt on each project change or pinch-zoom; `EditorThumbnailCache` buckets thumbnail times to 0.5s so re-layouts mostly hit the cache.
- **`VideoEditorViewController.swift`**: every edit goes through `apply(_:)`, which snapshots the whole `EditorProject` for undo/redo and rebuilds the player item. Clips come from `PHPickerViewController` (iOS 14+, `.current` representation to avoid transcoding; `UIImagePickerController` with passthrough below 14) and audio from the Files picker, each copied into a per-editor temp folder that's deleted on close. Export uses `AVAssetExportSession` with the chosen 720p/1080p/4K preset (falling back to HighestQuality if incompatible) and saves via `PhotosAlbumSaver` with `albumName: nil`, so exports go **straight into the Photos library, not the GameShutter folder**. That folder holds only highlight clips, the editor's source material. After saving, `offerToShare` presents `ShareDestinationsViewController`, a dimmed card with two image buttons, **Instagram** and **More**, plus **Not Now**. The choice runs after the card dismisses. Instagram's image is the `InstagramIcon` image set in `Assets.xcassets`: 2x/3x PNGs (152/228 px) made from the user-supplied logo JPEG, with the white JPEG corners masked to transparent along the logo's own corner radius. More is drawn by `fallbackTile` (an ellipsis on a gray tile), which also stands in for Instagram if its image set is missing. Instagram opens `instagram://library?LocalIdentifier=<id>` with the just-saved asset preselected; `PhotosAlbumSaver.save`'s completion returns the new asset's `localIdentifier` for this. No `LSApplicationQueriesSchemes` entry is needed, since `open(_:)` just reports failure if Instagram isn't installed. More presents `UIActivityViewController` with the exported file (Messages, AirDrop, TikTok, WhatsApp…). Direct TikTok and Facebook buttons were tried and removed: TikTok has no public video handoff without its OpenSDK client key, and Facebook Reels needs a Meta App ID. Don't delete the shared file from the sheet's completion handler. TikTok's share extension hands off to its app after the sheet reports completion, so deleting there broke the share. Instead the file is moved into the editor's temp folder, which `close()` deletes. The export is saved with `deleteAfterSave: false`; the Instagram and Not Now paths delete it right away.
- **`HighlightFoldersViewController.swift`**: the folder browser described above.
- **`PhotosAlbumSaver.swift`**: shared by highlight clips and editor exports; `dateAlbums()` lists the folder's albums for the browser. Saves into a **GameShutter folder › `yyyy_MM_dd` album** (highlights), or into the library with no album when `albumName` is nil (editor exports), one save at a time on a serial queue so concurrent saves can't create duplicate albums.

**Simulator testing caveat**: the iOS 26 simulator ignores `simctl privacy grant photos`, and its permission prompts outlive the app process, blocking later launches until the simulator is rebooted. Photos saving can only really be verified on a device.

### Zoom

Two independent zoom paths exist and both write to `vManager.deviceZoomFactor`:
- **Pinch gesture** (`CameraViewController.handlePinchGesture`): captures `device.videoZoomFactor` as `pinchStartZoomFactor` on `.began`, then scales by `pinch.scale` on `.changed`, clamped to `[minAvailableVideoZoomFactor, activeFormat.videoMaxZoomFactor]`.
- **Programmatic** (`videoManager.changeDeviceZoom(percent:)` / a duplicate in `CameraViewController`): maps a `0...1` percent to `[1, maxZoomFactor]` where `maxZoomFactor` is the *min* of front/back max zoom (so switching cameras doesn't exceed either device's range).

`deviceZoomFactor` is reapplied to whichever camera becomes active in `switchCamera()`.

### View Controllers

- `CameraViewController` — the only functional screen; owns `videoManager`, drives the record/pause/resume/highlight buttons and the elapsed-time label (`keep_timer`, ticking via `Timer.scheduledTimer`). Recording state persists across backgrounding: `appMovedToBackground` force-stops and saves; `appwillTerminate` does the same on termination.
- `settingViewController` — a single-row table: a static "Highlight Duration: 10" label, not yet connected to `vManager.HighlightDuration`. Nothing reads `UserDefaults` anymore.

### App Lifecycle

Classic `UIApplicationDelegate` lifecycle — there is no `SceneDelegate`/`UIApplicationSceneManifest`. `AppDelegate` is a near-empty stub (no BLE state-restoration handling on this branch) with a `window` property; the UI loads from `Main.storyboard` via `UIMainStoryboardFile` in Info.plist. Backgrounding/termination handling lives in `CameraViewController` via `NotificationCenter` observers, not in `AppDelegate`.

### Key Constraints

- **Landscape only, except the video editor**: Info.plist lists portrait too, but only so the editor can use it. `AppDelegate.orientationMask` (returned from `application(_:supportedInterfaceOrientationsFor:)`) keeps every other screen landscape. `openVideoEditor` widens it to `.allButUpsideDown` before presenting. The editor's `preferredInterfaceOrientationForPresentation` follows how the device is held: device portrait → portrait, device landscape → the *mirrored* interface landscape (device `.landscapeLeft` = interface `.landscapeRight`), and face-up/unknown → the current scene orientation. It rotates with the device afterwards. `CameraViewController.viewDidLoad` starts device-orientation notifications for the app's lifetime, because `UIDevice.orientation` reads `.unknown` right after they start (and in the iPadOS 26 simulator, always). Its `close()` resets the mask and calls `setNeedsUpdateOfSupportedInterfaceOrientations()` (iOS 16+) on the camera screen so it snaps back to landscape. A new screen that should be portrait has to widen the mask the same way. On iPadOS 26 the system doesn't rotate the display for the landscape-only camera screen; it shows it as a landscape window.
- **iPad primary target** — layout assumes a large screen, though `TARGETED_DEVICE_FAMILY = "1,2"` means the app also builds and installs on iPhone.
- **Physical device required** — camera capture and Photos export do not work in the simulator.
- **Hand-edited project file** — `objectVersion = 48` has no synchronized file groups, so adding or removing a source/resource file means adding or removing its `PBXBuildFile`, `PBXFileReference`, group, and build-phase entries in `project.pbxproj` by hand, not just touching the disk.
- **GLKView / EAGLContext** — preview rendering uses OpenGL ES 2 (deprecated since iOS 12); no overlay is composited into the live preview, only into recordings (the watermark).
